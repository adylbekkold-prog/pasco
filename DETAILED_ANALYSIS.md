# Детальный анализ PASCO Lab Portal - Проблемы с ссылками и структурой

## 📋 Статус анализа: 15 апреля 2026 г.

Проект работает корректно на `http://localhost:3000` но содержит ряд навигационных и структурных проблем.

---

## 🔴 КРИТИЧЕСКИЕ ПРОБЛЕМЫ

### 1. **Футер: Мёртвые ссылки "Системные ссылки"**

**Файл:** [app/(public)/layout.tsx](app/(public)/layout.tsx#L57-L65)

**Проблема:** Три ссылки в разделе "Система" указаны как текст без гиперссылок:
- ✗ "Hybrid режим" 
- ✗ "Supabase mirror"
- ✗ "Локальные файлы"

```tsx
// Неправильно - это просто текст, не ссылки:
<div className="mt-5 grid gap-3 text-sm text-slate-600">
  <div>{copy.systemLinks[0]}</div>  // "Hybrid режим"
  <div>{copy.systemLinks[1]}</div>  // "Supabase mirror"
  <div>{copy.systemLinks[2]}</div>  // "Локальные файлы"
</div>
```

**Эффект:** Пользователи видят текст, но не могут перейти. Выглядит как ошибка.

**Решение нужно:**
- Либо создать маршруты для этих страниц
- Либо заменить на `<Link>` компоненты
- Либо удалить, если они не нужны

---

### 2. **Футер: Все ссылки каталога ведут на /labs**

**Файл:** [app/(public)/layout.tsx](app/(public)/layout.tsx#L57-L62)

**Проблема:** Три ссылки каталога ("Новые лаборатории", "Предметы", "Классы") все ведут на один и тот же путь:

```tsx
<Link href="/labs">Новые лаборатории</Link>
<Link href="/labs">Предметы</Link>
<Link href="/labs">Классы</Link>
```

**Эффект:** Нет корректной навигации по разным разделам каталога. Нарушает ожидания пользователя.

**Ожидаемое поведение:**
- "Новые лаборатории" → `/labs?sort=new`
- "Предметы" → `/labs` (по умолчанию) или отдельная страница фильтра
- "Классы" → `/labs?view=grades` или аналогично

## 🟡 ПОТЕНЦИАЛЬНЫЕ ПРОБЛЕМЫ

### 3. **Неиспользуемый компонент NavbarLinks**

**Файл:** [components/NavbarLinks.tsx](components/NavbarLinks.tsx)

**Проблема:** Компонент `NavbarLinks` экспортируется, но **нигде не импортируется** в приложении.

```tsx
// components/NavbarLinks.tsx - существует, но не используется
export default function NavbarLinks({ links }: { links: NavbarLinkItem[] })
```

**Эффект:** Мертвый код, может вызвать путаницу. Занимает место в коде без назначения.

---

### 4. **Недостаточно защищённый маршрут /admin**

**Файл:** [app/(admin)/layout.tsx](app/(admin)/layout.tsx)

**Проблема:** Хотя есть страница логина в `/admin/login`, прямой доступ к `/admin` может быть открыт без проверки.

**Ожидаемое:**
- Если пользователь не авторизован → редирект на `/admin/login`
- Если авторизован → показать панель управления

---

### 5. **Различное поведение фильтрации каталога**

**Файл:** [app/(public)/labs/page.tsx](app/(public)/labs/page.tsx#L65-L70)

**Проблема:** Логика фильтрации требует выбора предмета:

```tsx
getLabs({
  subjectSlug: params.subject,
  gradeLevel: params.subject ? undefined : params.grade ? Number(params.grade) : undefined,
  search: params.subject ? undefined : params.search,
  locale,
})
```

**Эффект:** 
- Если выбран предмет → можно уточнить класс и поиск работает
- Если нет предмета → класс игнорируется, поиск работает

Это может запутать пользователя при использовании фильтров.

---

### 6. **Отсутствуют специальные страницы для фильтров**

**Проблема:** Нет отдельных маршрутов для:

```
❌ /subjects (все предметы с описанием)
❌ /grades (все классы с описанием)  
❌ /categories (если будут категории)
❌ /popular (популярные лабораторий)
❌ /recent (новые лаборатории)
```

**Эффект:** Все фильтры реализованы через query-параметры `?subject=`, спрятаны в URL. Неудобно для SEO и пользователя.

### 8. **Пути к изображениям и файлам могут быть недоступны**

**Файл:** [app/(public)/labs/[slug]/page.tsx](app/(public)/labs/[slug]/page.tsx#L80-L90)

**Потенциальная проблема:**
```tsx
<img alt="..." src={lab.image_url} />
```

Если `image_url` содержит неправильный путь или файл удалён → 404 ошибка изображения.

**Эффект:** Лaby выглядят неполными.

---

### 9. **Отсутствует 404-страница для каталога**

**Файл:** Есть [app/(public)/not-found.tsx](app/(public)/not-found.tsx)

**Проблема:** Когда пользователь вводит несуществующий slug лаборатории, работает трёхточечная логика:

```tsx
try {
  lab = await getLabBySlug(slug, locale)
} catch (error) {
  if (isDataNotFoundError(error)) {
    notFound()  // Показивает not-found.tsx
  }
  // ...
}
```

✓ Это правильно, но пользователь должен видеть дружелюбное сообщение.
